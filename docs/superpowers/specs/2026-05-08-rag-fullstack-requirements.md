# RAG 全栈应用 — 需求规格

**状态**：已确认  
**日期**：2026-05-08  
**栈**：Go 后端、React 前端、RAG（检索增强生成）

---

## 1. 目标与范围

构建单机单用户可用的 RAG 应用：用户上传文档，系统建立索引；用户通过对话提问，系统基于检索到的片段生成回答，并展示引用与溯源信息。

**明确不包含（当前版本）**

- 用户登录与多租户隔离（单机受信使用）。
- PDF 图片层 OCR。
- 分块策略的可配置项（仅内置默认值）。
- 关键词与向量混合检索。
- 前端直连持有密钥的第三方 API。

---

## 2. 需求场景

| ID | 场景 | 角色 | 行为 | 成功标准 |
|----|------|------|------|----------|
| S1 | 知识入库 | 用户 | 上传文档（见 3.1 支持格式） | 解析、分块、向量化完成或失败原因可感知；支持删除后索引与文件一致（见 5.2） |
| S2 | 可检索问答 | 用户 | 在对话中提问 | 回答基于检索上下文；SSE 流式输出 |
| S3 | 溯源 | 用户 | 查看回答依据 | 展示引用片段及来源文档、可解析时的位置信息 |
| S4 | 会话与历史 | 用户 | 多轮对话、历史查看 | 会话列表与消息可加载；消息与引用元数据保留策略见 5.1 |
| S5 | 停止生成 | 用户 | 主动停止 | 前端可停止；后端取消进行中的上游请求，减少无效消耗 |
| S6 | 运维 | 开发者 | 部署与排错 | 可配置超时与日志；日志不记录完整 prompt（见 5.1） |

---

## 3. 功能需求

### 3.1 文档与索引

- **F1**：提供文档上传入口（HTTP 上传即可满足 MVP）。
- **F2**：不做 OCR；无文本层的 PDF 需明确错误提示或不支持。
- **F3**：分块策略**不可配置**，使用产品内固定默认值（实现时需将具体数值写入设计与代码常量，便于复现）。
- **F4**：对分块结果生成向量并写入向量存储；支持按文档删除索引（删除规则与源文件一致见 5.2）。
- **F5**：检索：给定 query，返回 Top-K 片段、分数及元数据（文档名、位置等）。
- **F6**：不做混合检索；仅采用单一检索方式（默认向量检索）。

### 3.2 生成与对话

- **F7**：聊天接口通过 **SSE** 向客户端流式返回生成内容。
- **F8**：服务端组装 prompt：系统说明 + 检索上下文 + 用户消息；遵守模型上下文长度限制。
- **F9**：响应需携带 **citations**（如 chunk id、摘录、来源文件/位置），供前端展示。
- **F10**：支持**停止生成**：客户端断开 SSE 或调用取消接口；服务端通过 `context` 取消对 LLM 的调用。

### 3.3 前端（React）

- **F11**：对话界面：输入、SSE 展示、停止生成。
- **F12**：文档区域：列表、上传、索引/处理状态（排队、处理中、就绪、失败）。
- **F13**：回答区域展示引用或可展开依据片段。
- **F14**：路由与布局按 MVP 合并或拆分均可，需覆盖对话与文档管理路径。

### 3.4 身份与部署假设

- **F15**：**单机单用户、无登录**；部署上依赖本机或受信网络、可选反向代理限制访问，不在本规格内规定具体网络拓扑。

## 4. 技术约束

| ID | 说明 |
|----|------|
| T1 | 后端使用 **Go**：统一提供 HTTP API、索引流水线、检索、调用 LLM、可选持久化。 |
| T2 | **密钥与第三方凭据仅存在于后端**；React **不**直连需密钥的模型或向量服务。 |
| T3 | 默认 LLM 提供方为 **DeepSeek**；在 Go 中定义 **可替换的 LLM 抽象接口**（如流式/非流式、messages、取消），DeepSeek 为默认实现，后续可增其他 provider 而不改核心业务编排。 |
| T4 | 架构选型：**方案 A** — 单体服务内完成上传、解析、嵌入、检索、对话编排；实现时模块边界清晰，便于未来拆分或引入异步 worker。 |

## 5. 非功能需求

### 5.1 数据保留与隐私（NF6）

- **会话消息**与**引用元数据**（用于溯源的 chunk 标识、来源、摘录定位等）：**保留期 30 天**，期满删除或匿名化（实现选一种并文档化）。
- **不**持久化存储**完整 prompt**（含拼装后的全量 system + 检索上下文 + 用户原文的完整串）；日志与排错以 `request_id`、阶段、错误码、耗时为主，避免打印用户全文。

### 5.2 文档与索引生命周期

- **原始上传文件**与**向量索引及可检索数据**绑定：**与索引同步删除**。  
  当文档从系统移除时，删除对应向量数据及对象存储/磁盘上的源文件，避免索引与文件长期不一致。  
  若删除任一步失败，需有重试或失败状态，避免长期孤儿文件或孤儿索引（具体两阶段顺序在实现设计中确定）。

### 5.3 性能（NF1，宽松参考）

以下为首版**宽松**目标，用于开发与告警基线，非严格 SLA；上线后按实测调整。

| 指标 | 宽松参考 |
|------|-----------|
| 检索延迟 | p95 ≤ **2 s** |
| 首 token（TTFT） | p95 ≤ **10 s** |
| 单轮流式生成总超时 | **120–180 s**（可配置，与上游一致） |
| 单文档入库（无 OCR） | p95 ≤ **5 min**（中等体积；大文件以进度/状态可观测为主） |
| API 超时建议 | 检索 **10 s**；LLM **与流式总超时一致** |

### 5.4 其他

- **可用性**：索引失败、上游超时、上下文超长等须有明确错误类型与前端可展示信息。
- **可观测性**：结构化日志、关键步骤耗时；指标可选。
- **配置**：模型名、Base URL、API Key、向量维度、DSN、超时等通过环境变量或配置文件注入后端。

## 6. 与历史讨论的对应关系

| 主题 | 结论 |
|------|------|
| 架构 | 单体方案 A |
| OCR / 分块配置 / 混合检索 | 不做 |
| 流式与停止 | SSE + 停止生成 |
| 用户模型 | 无登录单机用户 |
| LLM | DeepSeek + 接口可替换 |
| 性能 | 采用宽松 NF1 表 |
| 30 天 | 仅会话消息 + 引用元数据 |
| 上传文件 | 与索引同步删除 |
| 前端密钥 | 不暴露给浏览器 |
